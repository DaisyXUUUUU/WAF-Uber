# 真实数据实验：从这里开始

此项目在原来的 `simulator.py` 上增加真实数据流程。原有合成模拟器、README 和 results_v2 均保留。

**数据来自 NYC TLC 官方公开的 2024 年 1 月大型网约车行程文件，筛选 Uber、非拼车记录。程序不生成用于正式实验的虚构订单。** 但司机初始数量、位置与替代派单后的轨迹仍是模型设定；结果不是对真实 Uber 服务率的还原。


在这个文件夹打开终端。先安装依赖（无需 API 密钥）：

## 2. 先检查，再下载和做小试验

```sh
python simulator.py --self-test
python -m unittest discover -s tests -v
python pipeline.py download
python pipeline.py prepare
python pipeline.py smoke
```

- `download` 下载官方月度 Parquet 与区域查询表，按块写磁盘，不把整个文件放入内存。文件可能较大，请保留数 GB 空间。显示已下载 MB；网络中断后重新运行，未完成文件会重新下载。
- `prepare` 每批读取 20 万行，筛选、生成各日请求、历史时间表、初始位置分布和数据审计。筛选区域不是全纽约，开始时会打印官方区域名称。
- `smoke` 只使用第一个验证日、第一种车队和第一个初始化种子，对比基线与一个非零权重。它用于检查可运行性与耗时，**不是最终结果**。

不建议直接点击 VS Code 的“运行 Python 文件”执行 `pipeline.py`，它需要步骤参数。请复制上面的终端命令。

所有路径以项目目录为准，不依赖终端当前目录。如果你在别处运行，请使用 pipeline.py 的完整路径。

## 3. 小试验正常后，进行参数选择和测试

```sh
python pipeline.py validate
python pipeline.py test
python pipeline.py report
```

也可以从下载开始一次完成全部步骤：

```sh

```

建议首次分步运行。正式 `all` 会完整运行验证和测试，不只是小试验。

- 验证期比较所有预设权重，按服务率最高选取；相同则优先平均等待较短，再优先较小权重。对每种车队分别选取。
- 允许选择零权重，绝不强制前瞻获胜。
- 测试期只比较基线和验证期选定权重，不依据测试结果重新选参数。
- 修改配置、数据或代码后，旧的权重选择会失效，要求重新验证。
- 每次运行创建新结果目录，不覆盖此前实验。相同配置的原始下载和清洗数据可复用。

若有多次测试结果，可以指定要汇总的目录：

```sh
python pipeline.py report --run-dir results_real/具体时间戳_test
```

## 4. 当前固定的小规模实验设计

配置文件为 `experiment_config.json`，不是模拟器内部默认参数。

| 项目 | 预设 |
| --- | --- |
| 来源月份 | 2024-01，HVFHV |
| 平台 | HV0003，即官方字典所列 Uber |
| 拼车 | shared_request_flag=N 且 shared_match_flag=N；未知标记不保留 |
| 封闭区域 | 161, 162, 163, 164, 170, 233；下载后用官方 lookup 打印名称 |
| 请求时间窗 | 纽约当地时间 17:00–19:00 |
| 历史日期 | 1/2–1/12 中配置列出的 9 个工作日 |
| 验证日期 | 1/16、1/17 |
| 测试日期 | 1/22、1/23、1/24 |
| 请求抽样 | 三个阶段均固定保留约 10%；按源文件行号和种子的哈希决定，不按方法结果选择 |
| 车队规模 | 8、12；模拟参数，不是从数据还原的真实司机数 |
| 初始化种子 | 2026、2027；同一天同一车队两策略位置完全相同 |
| 权重候选 | 0、3、10；单位为每个潜在服务机会折算的接驾分钟数 |
| 前瞻窗口、场景数 | 30 分钟，2 个历史日场景 |
| 匹配间隔、总等待上限 | 1 分钟、8 分钟 |
| 局部搜索 | 最多 2 轮、20 个候选；只调整司机，不更换基线已选择的当前订单子集 |

这是一项**预设区域内的抽样请求流实验**，不是全量 NYC Uber 模拟。抽样会改变供需与竞争强度，应作为局限报告。如果扩大规模，需要预先修改配置，重新准备、验证和测试，不能只挑获胜设置。

为了避免纯 Python 状态更新和局部搜索在超大输入上失控，单日请求超过 `max_requests_per_day` 会明确停止，绝不会偷偷截断订单。先检查 `daily_counts.csv` 再决定规模。

## 5. 行程时间如何估计

只使用历史日期、选定区域内的实际载客时长，构造静态 OD 中位数表。这是对空车接驾时间的代理，并非观测到了司机原位置到上车点的真实接驾行程。

稀疏区域对的回退顺序：有足够记录的 OD 中位数；否则区域间用历史 OD 图的最短时间路径；仍缺失则使用历史跨区总体中位数。同区缺数据使用历史同区总体中位数，全部缺失时明确标记为 3 分钟假设。每个区域对的来源和样本数都保存在 `travel_times.csv`。

该表固定且不随时段变化，是当前 Q2 允许的确定性时间模型的简化。**不读取测试订单的实际完单时间来安排模拟司机释放。** 同一张历史表用于可行性、实际模拟和前瞻。

输入质量筛选要求有效时间戳、请求不晚于上车、等待不超过 180 分钟、载客时长在 0.5–180 分钟之间。**不会用 8 分钟的模型等待上限预筛真实订单**，否则会人为剔除难服务的请求。

公开文件没有可用的唯一行程 ID。本程序统计相同时间/地点签名，但不自动去重，以免把同一时间同一区域的不同乘客删掉。

## 6. 输出去哪了，发哪些文件

### data/raw/

原始 Parquet、区域查询 CSV 和 `.source.json`。后者记录官方 URL、下载时间、字节数、校验和。

### data/processed/配置标识/

- `data_report.json`：筛选计数、原始来源、采样比例、时间划分和局限。
- `daily_counts.csv`：每日抽样前后订单数。
- `travel_times.csv`：全部区域对时间估计与回退类型。
- `requests_日期.csv`：模型真正读取的请求；没有测试期实际完单时间。
- `initial_distribution.json`：历史订单起点分布，用于初始车队抽样。
- `selected_zones.csv`：官方区域名称。

### results_real/时间戳_smoke 或 _validate 或 _test/

- `summary.csv`：每个日期、种子、车队和策略的结果及诊断。
- `run_manifest.json`：配置、版本、代码和数据标识。
- `selection.json`（验证）：冻结的权重和选择依据。
- `selection_used.json`（测试）：本次使用的验证期选择。
- `*_trips.csv`、`*_decisions.csv`、`*_initial.json`：逐单、逐轮和初始位置记录。

`report` 另生成：

- `comparison.csv`：基线与选定方法汇总。
- `paired_differences.csv`：同日、同种子差异；服务率差值单位为百分点。
- `uncertainty.json`：按测试日期聚类的探索性 bootstrap 区间。只有三个测试日，不能据此做强统计结论。
- `results_table.tex`：可复制进报告的英文表格；零权重时明确标注。
- `RESULTS_README.md`：解释口径。

**首次运行后发给研究助理：** `data_report.json`、`daily_counts.csv`、smoke 的 `summary.csv` 和 `run_manifest.json`。不必上传整个原始大文件。

## 7. 方法没有改变，但实现提速了

保留原 `simulator.py` 的状态更新和局部搜索。真实实验调用 SciPy 求解器完成匹配：当前匹配仍先最大数量再最小成本；前瞻仍是每车最多一次潜在服务、每单最多计一次。快速求解器已用随机小实例与原求解器核对目标值。

前瞻场景属于假设，不是实际预订。未出车司机停在原地；已忙和新出车司机按完单时刻释放；潜在订单出现前不得出发。局部搜索不是全局优化，前瞻忽略当前遗留积压订单并只看每车下一单，这些近似仍需在报告中说明。
